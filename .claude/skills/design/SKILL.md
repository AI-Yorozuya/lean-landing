# design・一頁式官網的設計知識

> 參考底：Anthropic `artifact-design`／`frontend-design`（anthropics/skills）的通用原則，取用適用於「一頁式、AI 代改、玩家零工程背景」情境的部分；三刀口與兩版 layout 是本 repo 家法。

## 三刀口（要動哪類，就只開哪個檔）

| 要改什麼 | 檔案 | 紀律 |
|---|---|---|
| 內容（字、連結、圖） | `site/index.html` | 招牌/CTA 散多處——**改完 grep 全出現點**（`<title>`、導覽列、SVG aria-label、關於、頁尾） |
| 氣質（色彩/字型/圓角） | `site/style.css` 的 token | **四個 block 全換**（`:root`、`@media dark`、`[data-theme=light]`、`[data-theme=dark]`）——只換一半＝深色模式會壞 |
| 骨架（排版/欄位/選單位置） | `site/layout-desktop.css`／`site/layout-mobile.css` | 桌機、手機各自打造，改一邊**零波及**另一邊 |

顏色**只**定義在 token、元件**永遠**吃 token——一個顏色若只活在某個 media／`[data-theme]` block 裡，就會在另一個主題下印出「這個主題的字、那個主題的底」，這是最經典的不可讀 bug（artifact-design 點名）。

## 元件詞彙（玩家指東西用的名字——教練講話一律用這套）

中文為主、英文附註：玩家在免費章學會中文那半就能指東西；英文那半是進 lean-erp 之後跟任何 AI／任何前端溝通的通用語，等於順手搭好詞彙橋。**不要自己另造名字。**

| 名字 | 是哪一塊 |
|---|---|
| 招牌 brand | 左上角店名（分頁圖示 favicon 跟著它的首字） |
| 導覽列 nav ／ 導覽連結 nav links ／ 導覽列聯絡鈕 nav cta | 最上面那條與其中的東西 |
| 選單鈕 menu button | 手機版左下角的圓鈕（桌機不出現） |
| 開場區 hero | 第一眼看到的整塊 |
| 標語 hero title ／ 開場介紹 hero description ／ 開場聯絡鈕 hero cta ／ 開場大圖 hero image | 開場區裡的四樣 |
| 亮點區 features ／ 亮點卡 feature card ／ 亮點標題 card title ／ 亮點說明 card description | 三張平行賣點 |
| 關於區 about ／ 關於標題 about title ／ 關於內文 about description ／ 關於區聯絡鈕 about cta | 自我介紹那段 |
| 頁尾 footer | 最下面那條 |

命名三條規矩（要加新元件時照這個取）：
1. **中文用店家講得出口的話,不用設計行話**——「開場區」不是「主視覺區」,「標語」不是「主標」。
2. **中英各說一次,不重複**——「開場區 hero」不是「開場區 hero section」（區＝section）;「開場聯絡鈕 hero cta」不是「…cta button」（鈕＝button）。
3. **講功能不講視覺輕重**——「關於區聯絡鈕」不是「次要鈕」;玩家心裡它就是另一顆聯絡鈕。
4. 排版用的容器不標（例如包住開場文字的那層 div）——玩家永遠不會指它,標了只是噪音。

**三個地方拿得到這套名字**：`site/index.html` 檔頭的對照圖（打開檔案就看到）、每個區塊的 `data-name` 屬性、以及第三幕產的 `架構圖.md`。

**認識元件開關**：本機預覽時右下角出現「顯示名稱」按鈕，按了每塊浮出全名＋虛線框。實作＝`script.js` 偵測 localhost／file:// 才生按鈕，切 `<body data-labels>`；樣式在 `style.css` 的 `[data-labels]` 區（關閉時一行都不套）。**上線版連按鈕都不會有**，`data-labels` 也絕不寫死進 HTML。

名牌排版的三條紀律（做錯就會壓到內容或被裁掉）：
1. **每個元件先空出自己的位置**（`margin-top: var(--label-gap)`），名牌坐在那塊空位裡（`bottom: 100%`）——不要用負 offset 疊在元件上。巢狀也成立：子元件的空位在父元件內部，各據各的。
2. **貼右緣的元件名牌靠右對齊**（`left: auto; right: 0`），否則長名字會超出視窗被裁。
3. **導覽列在認識模式下取消 sticky**（`position: static`），否則它長高之後會蓋住下面的內容。

改完一定要驗，不能目測：逐一算出每個名牌的矩形，跟頁面上所有內容元素做交集檢查，**桌機與手機都要 0 重疊、0 裁切、無橫向捲動**。

## 兩版 layout 主張（本站的設計立場）

手機版不是桌機版硬縮的——**桌機一版、手機一版，各自做好**。AI 時代維護兩版不貴，不必再把一份 layout 凹到兩種螢幕都將就。

- 斷點 768（`<link media>` 切換，零 JS，轉橫豎自動切）。
- 手機版設計語彙：視覺在上、單欄直下、**選單收左下拇指區**（固定圓鈕、往上展開，單手按得到）、頂欄只留招牌。
- 重排手機版＝整檔改 `layout-mobile.css`；桌機同理。
- ⚠ 座標陷阱：`backdrop-filter` 會把 fixed 子元素的定位基準搶成自己（Chrome 行為）——手機版 `.nav` 用實色就是為了讓左下浮鈕真的釘在視窗左下，別把毛玻璃加回手機版。

## 階層與版型（一屏一件事）

- 標語最大（serif、clamp 縮放）→ 自介 muted 次之 → CTA 對比最強（accent 底）。
- **大膽只花在一處**：整頁唯一的亮點＝CTA。其他一切保持安靜——亮點跟底色打架時，降飽和或往鄰近色靠，不要再加第二個亮點。
- 內文行寬守 ~60–65ch（`.lede` 已鎖 60ch）；標題保留 `text-wrap: balance`；若加大寫英文標籤，配一點 letter-spacing。
- 亮點卡 desc **≤ 40 字**（15px 版型，貪多爆版）；整頁只有一種 CTA 動作，別放兩顆不同目的的按鈕。
- 間距用容器的 `gap`（flex/grid），不用零散 margin 疊——現有 CSS 已如此，改版時守住。
- **結構＝資訊**：編號、分隔線、eyebrow 標籤要encode內容裡真實存在的東西，不是裝飾。編號（01/02/03）只有內容真是序列才用。
- 動效克制：散落的特效是 AI 臉的一種。目前全站只有 hover 微動——要加動效先問「它服務什麼」，並尊重 `prefers-reduced-motion`。

## AI 臉黑名單（Q3-參考路生成新氣質時對照自檢）

AI 生成的設計會聚在幾個套路臉。玩家自己點名要的照做（他的話永遠贏）；**沒指定時不要把自由花在這些預設上**：

- 米白底＋serif 大標＋赭紅/陶土 accent（cream + terracotta）
- 近黑底＋一點酸綠或朱紅
- 紫藍漸層 hero 配白底
- Inter／Space Grotesk 當「安全牌」字型
- emoji 當章節標記、全部置中、到處 rounded-lg、圓角卡上加 accent 條

中性色是**挑的**不是預設的：灰往 accent 的色相偏一點，看起來就是選過的；純中灰看起來是沒想過的。

## 照片與氣質是一組，不能分開挑

主圖是整頁**面積最大、最搶眼**的東西——氣質 token 再怎麼調都蓋不過它。所以換照片和選氣質要一起決定（配對表在 `../landing-page/行業範例庫.md`）。

判斷方法（**題材先於顏色**）：
- **題材**：氣質有它的人格——專業沉穩是西裝、溫暖手作是圍裙、明亮活潑是運動鞋。照片主體要跟那個人格是同一種場合。**題材不對，顏色再準也沒救**（西裝風配麵包照就是怪）。
- **冷暖**：照片偏橘紅黃＝暖，偏藍青＝冷。暖照片配冷主色（或反過來）就是互補色對撞，整頁會打架。
- **飽和**：接近黑白灰的照片百搭，怎麼配都行；顏色越鮮豔越要遷就它——這時該讓氣質去配照片，不是照片去配氣質。

反例（實測）：`bakery.jpg` 色相 9° 暖橘 × 專業沉穩主色 209° 藍，差 200°；照片明度 38% 很暗，底色卻是純白。三重打架。

## 氣質 token 系統

- 選氣質＝整組換 `site/style.css` 的 token 四 block；四款預設（極簡黑白／溫暖手作／專業沉穩／明亮活潑）的 light＋dark 全套值在 `氣質庫.md`（同資料夾）＋ style.css 檔尾註解。
- **參考路流程（frontend-design 的三步）**：① 先寫迷你設計計畫——4–6 個具名色值＋兩役字型（display/body）＋一句版型概念；② 對上面的黑名單自檢，像 generic 的部分改掉；③ 才落 token。
- 參考網站只抽**抽象特質**（配色/字型氣質、版型節奏、語氣）→ token＋版型；**絕不搬 logo、圖、原句、品牌名**。
- 抽出 light 值要**同步推導 dark 值**（氣質庫規則：bg＝近黑帶一絲主色調、ink 亮、accent 提亮 10–20%、line 低對比）——深色不是反轉，是同一套氣質的夜間版，兩邊都要讀得清楚。
- 字型配對是氣質的一部分（serif 標題×sans 內文是預設配法；氣質可換 `--serif`/`--sans`），給每個 face 留真實 fallback stack。
- 內建四款蓋不住 → 取兩字名、light＋dark 全記進 `氣質庫.md`（複利沉澱）。

## 文案也是設計材料（教練代擬時過這關）

- 站在客人那一側命名：他認得的詞，不是系統詞。
- 主動語態；按鈕寫清楚按了會發生什麼（「加 LINE 聊聊」勝過「了解更多」）。
- 具體勝過聰明；錯不起的資訊（電話、地址、價格）一律玩家點頭才算數。

## favicon＝玩家的門牌，不是我們的

分頁圖示用**招牌首字＋氣質主色**的 SVG data URI（零檔案、跟著換氣質走）——改招牌要一起改首字編碼，改氣質要一起改色碼。熊只出現在頁尾「用 AI 萬事屋做的 🐻」署名，**絕不進 favicon**：分頁是他的門牌，掛我們的 logo 等於在他店門口掛我們的招牌。玩家給了真 logo 就換成檔案。

## 驗收四件（改完自查，漏一件算沒過）

① `<title>`＝招牌名　② CTA 真的按得動（電話真的撥／LINE 真的開）　③ 手機版不破（縮窄跨 768 看兩版都對、左下選單能開能點）　④ 深色模式不醜（切一下看——重點抓「只在單一主題定義過的顏色」）
