# 亮相序列・上線與上線後支線（Workers Static Assets）

> 玩家喊「上線」時 Read 本檔照跑。含：部署⓪–⑤、GitHub 備份（第五幕）、自訂網域（第五・五幕）、通關。

→ 玩家喊「上線」＝**亮相序列**（Cloudflare Workers Static Assets）。

> 實測基準（2026-08-28，wrangler 4.127，全程 27 秒）：上傳 19 檔 3 秒 → 部署 10 秒 → 生效 5 秒；**網址第一次 curl 就 200，沒有空窗**；wrangler 印出的就是最終網址。**照順序跑、別自己簡化**：

**⓪ 先把 preview 開在他眼前。** 把 `site/index.html` 開在內建瀏覽器（同開窗）——「這就是等下要上線的樣子。」他要親眼看著這一版上網路，不是盲發；preview 開著不動，直到亮相打開真網址。

**① 部署工具進場（本劇本唯一需要 Node 的時刻）。**
台詞：「上線要用一個部署工具，我先確認你電腦有它需要的東西，一兩分鐘。」
- `node --version` ≥ 22 才過關；缺／太舊 → mac `brew install node`（沒 brew 用官方安裝器）／Win `winget install OpenJS.NodeJS.LTS`；裝完**開新終端機**再驗一次。
- 過關 → `npm install`（只裝鎖版 wrangler：「搬部署工具進來，約半分鐘」）。

**② 檢查 CF 帳號**（沒有→「幫你的網站辦個門牌處」當場辦，是價值兌現不是門檻）
- **能同框就同框**：環境有內建瀏覽器面板（開窗用的那個）→ 把 `dash.cloudflare.com/sign-up` 直接開在裡面，玩家不用跳出去。教練只導頁，**表單一律玩家自己填**。內建開不順（跳機器人驗證、載不動）→ 退回系統瀏覽器，不糾結。
- 講清楚交接方式：「註冊好回來跟我說一聲就行——**帳號密碼不用給我、也不用打在對話裡**，等下跳出授權頁，你按一下就好。」帳密永遠不進對話。
- ⚠ **註冊完要確認他「已經在瀏覽器裡登入」才進下一步**（實測 2026-08-28 踩到）：授權流程**沒有帳號選單**，它直接authorize瀏覽器當下登入的那個 Cloudflare 帳號。他如果剛註冊完沒登入、或瀏覽器還登著別的帳號，授權出來的會是錯的帳號，而且不會有任何警告。
  → 一句話帶過：「先確認你現在瀏覽器裡登入的是剛辦的那個帳號——等下授權會直接用它，不會再問你要哪個。」

**③ 授權：`npx wrangler login`**
- **開跑前先講這句**（授權頁會列一長串權限，玩家在這裡最容易退縮）：
  「等一下瀏覽器會跳出 Cloudflare 的授權頁，上面**會列一長串權限**——那是這個工具的通用清單，不是我們要用的。我們只會用到其中一項：把你的網站檔案放上去。看到就按綠色的 **Allow**。」
- 這個指令會**卡住等他授權**：背景跑，別讓自己 timeout。
- **授權頁一定要開在「登入著正確帳號的那個瀏覽器」**：剛剛註冊若是在內建瀏覽器做的，就把授權網址貼進**同一個內建瀏覽器**開（localhost 回呼同機都通）——別讓 wrangler 自動開系統瀏覽器，那邊的 session 可能是別的帳號或根本沒登入。
- **要換帳號時**：`npx wrangler logout` 只清掉本機憑證，**不會影響瀏覽器的登入狀態**——所以還要在瀏覽器登出 Cloudflare，或用無痕視窗開授權網址，否則又會授權到同一個舊帳號。
- **想自己控制在哪開**：`npx wrangler login --browser false` 會只印網址不自動開瀏覽器（管線會擋住輸出，別接 `| tail`）。
- **授權完自己驗一次**：`npx wrangler whoami` 確認 email 與 Account 是他要的那個，再往下部署。授權錯帳號而不驗，會一路部署到別人的帳號上。

**④ 先問網址名——絕不代取。** 網址是他要傳給客人的東西，取名權是他的。
「上線前先決定你的網址名。我建議用 `{招牌名的英文或拼音}`——這樣可以嗎？想換直接說。」
- 只吃**小寫英數與連字號**：中文招牌一定要轉拼音／英文，給他挑、他點頭才算數。
- 選定 → 教練把 `wrangler.toml` 的 `name` 改成這個名字（這是他的 repo，名字就該是他的）。

**⑤ 設帳號代號——⚠ 只有這一拍能設，過了就再也改不了**

> 位置很關鍵：**必須在③授權之後**（要用到授權拿到的 token）、**且在⑥部署之前**（部署會自動生成代號，生成後 API 就鎖死）。

workers.dev 網址有兩層：`{網址名}.{帳號代號}.workers.dev`。**帳號代號全帳號共用**，之後每個作品都掛它下面。

真帳號實測（2026-08-28，兩個帳號）：
- Cloudflare **不會問**，第一次部署時直接拿 email 帳號名生成——`peiran.hsu@gmail.com` → `peiran-hsu`。玩家的信箱帳號就印在他要傳給客人的網址上。
- 教練代跑一定是**非互動模式**（telemetry `isInteractive: false`），所以 wrangler 那個「要不要註冊 subdomain」的詢問**不會出現**。這不是意外，是必然。
- 設定 API **只能在還沒有代號時設，不能改既有的**（實測 PUT 既有值回 `10036 Account already has an associated subdomain`）。
- **一旦部署過就只剩後台能改**，而且後台在「還沒有任何 worker」時根本不顯示那個區塊——所以「部署後再補救」是最差解。

→ 所以**部署前**跑這一拍（教練代跑，玩家只出一個名字）：

```bash
# 讀 wrangler 自己存的授權（玩家本機、他自己的 token）——不印出來、不寫檔、不進對話
TOKEN=$(grep -E "^oauth_token" "$HOME/Library/Preferences/.wrangler/config/default.toml" | head -1 | sed 's/.*= *"//; s/"//')
ACC=$(npx wrangler whoami 2>/dev/null | grep -oE "[0-9a-f]{32}" | head -1)

# 先看有沒有
curl -s -H "Authorization: Bearer $TOKEN" \
  "https://api.cloudflare.com/client/v4/accounts/$ACC/workers/subdomain"

# 沒有 → 設成玩家決定的名字（同網址名的命名規則，他點頭才算數）
curl -s -X PUT -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  --data '{"subdomain":"{玩家決定的代號}"}' \
  "https://api.cloudflare.com/client/v4/accounts/$ACC/workers/subdomain"
```

台詞：「你的網址會長這樣 `{網址名}.{代號}.workers.dev`。後面那段是你的**帳號代號**，以後你做的每個網站都會掛在它下面，所以現在一起想好——用你的招牌拼音就行。」

- 已經有代號了（回傳有值）→ 唸給他聽問要不要換；要換只能帶他去 dash.cloudflare.com → Workers & Pages → 右側 **Your subdomain → Change**（教練代跑不了）。
- **鐵律：代號確認之前，網址一個字都不准發出去。**
- Windows 的憑證路徑不同（`%APPDATA%\.wrangler\config\default.toml`）。`仍需實測`
- 全新帳號（完全沒代號）的 GET 回傳形狀與 PUT 成功案例 `仍需實測`——本輪兩個帳號都已有代號，只驗到「既有的改不動」這一半。

**⑥ 部署＋揭曉**
```
npx wrangler deploy
```
（讀 `wrangler.toml`：`name`＝玩家取的名、`[assets] directory = "site"`——上傳的就是他一路看著的那個資料夾，**沒有 build、沒有轉換**。）
- 部署完**回讀輸出裡的網址**再給他：跟他選的名字不一樣就講白、問要不要換，**絕不默默接受**。
- 仍然**自己 curl 一次確認 200 再喊他打開**（首次部署實測零等待）。
- ⚠ **改完代號後 curl 可能一直 000，那多半是你自己機器的 DNS 快取**（實測：舊網址的否定結果被本機解析器記住，`dscacheutil -flushcache` 也沒用）。別誤判成部署失敗——用 `dig +short {網址} @1.1.1.1` 拿到 IP，再 `curl --resolve {網址}:443:{IP}` 驗，通了就是真的上線了，玩家那邊不受影響。
- 打開之後多一拍（本課核心教學句的實體）：「看個彩蛋——在網頁上按右鍵『檢視原始碼』：**跟你電腦裡那份是同一個檔案**。網站放上雲端，程式還是在看的人的瀏覽器裡跑。」

**第五幕・保險（亮相後輕提一次，選配不糾纏）**
「網站的原稿都住在你這台電腦裡。想多一層保險（電腦壞了、換電腦都找得回來），我幫你**備份上雲端**：辦一個免費 GitHub 帳號就行，兩分鐘。現在辦，或以後說『備份』都可以。」
→ 願意＝辦個家三步（教練代跑，玩家只按授權）：
  ① `gh auth login`（瀏覽器授權；沒裝 gh → mac `brew install gh`／Win `winget install GitHub.cli`）
  ② `gh repo create {招牌名拼音或英文} --private --source=. --push`
  ③ 「備份好了——以後每次存檔我都會順手同步上去。」PROGRESS 記備份（repo 網址）。
→ 不要 → 「好，隨時說『備份』就辦。」不再提。
時機紀律：**只在亮相後**；絕不在裝修中插註冊、絕不與 CF 註冊疊同一拍。

**第五・五幕・自訂網域（需求觸發，絕不主動推）**

> ⚠ 待實測：CF 後台買網域的實際選單路徑、買完是否自動建好 zone、憑證要等多久——第一次真的帶人走完，把實際畫面補回本節。

**只在他自己開口才跑**：「這網址好醜／不夠正式／我要印名片／可以用我自己的網址嗎」。他沒問就當這一拍不存在——免費層的招牌是「免費上線」，主動兜售年費會把招牌砸了。

**他說「我買好網域了，帶我接上去」** → 錢已花、意願已定：跳過確認與購買（下面 1–2），直接第 3 步接線＋第 4 步驗收，別再重問一次要不要辦。

先確認他真的要（待決合法，不慫恿）：
> 「先講清楚：`{現在的網址}` 一樣能收客人、Google 一樣找得到，不換完全沒問題。換自己的網址是為了名片和招牌上好看——**這要年費，一年約台幣三百多，付給 Cloudflare 不是付給我們**。要辦嗎？」

要辦 → 走 `.com`（**買在 Cloudflare，跟網站同一家**，不用再辦帳號、不用碰 DNS）：
1. 先問名字，只吃小寫英數與連字號；中文招牌轉拼音或英文，**他點頭才算數**（同亮相序列④，取名權是他的）。
2. 帶他到 CF 後台 → **Domain Registration** → 搜名字。**這一拍教練代跑不了**（在他的瀏覽器裡、而且要刷卡）——講明白「這幾步我只能在旁邊帶，付款你自己來，我不碰你的卡」。
3. 買完 → 回 **Workers & Pages → 他的專案 → Settings → Domains & Routes → Custom domain** → 加上新網址。
4. **驗收照亮相序列⑥的紀律**：自己 curl 到 200 再喊他打開，別讓他第一眼看到憑證還沒發好的錯誤頁。
5. PROGRESS 記「自訂網域：{網址}」。原本的 `*.workers.dev` 不關、兩個同時通——講一句讓他安心。

**他堅持要 `.tw`** → 不勸退也不慫恿，把代價講白讓他選：
- **Cloudflare 不賣 `.tw`**（Registrar 的 ccTLD 只支援 .ca/.co.uk/.nz/.mx/.co 那幾個），得去 TWNIC 認證的註冊商買（Gandi 等），牌價約 NT$744/年，比 `.com` 貴一倍多。
- 而且會多兩拍：CF 後台 **Add a site** 把網域建成 zone → 回註冊商**把 nameserver 換成 CF 給的兩組** → 等生效（可能要幾小時）→ 才回 Workers 加 Custom domain。**Workers 的自訂網域硬性要求 nameserver 在 Cloudflare**（外部 DNS 掛 CNAME 這條路不存在），繞不過。
- 講法：「`.tw` 台灣味比較夠，但要多辦一個註冊商的帳號、多刷一次卡、中間還要等生效。你要的是名片好看的話，`.com` 今天就能好；一定要 `.tw` 我也帶你走，只是慢一點。」

## Boss「亮相」（通關）

通關＝拿到 `*.workers.dev` 真網址、當場打開。
台詞：「這頁現在活在網路上了。傳給一個人看看——**等第一則不是你自己填的詢問進來**，你就正式開張了。」（第一則真詢問＝開張徽章，記進 PROGRESS，不設閘。）
